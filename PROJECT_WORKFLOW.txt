--------------------------------------------------------------------------------
STEP 1: IDEA -> PRD (PRODUCT REQUIREMENTS DOCUMENT)
--------------------------------------------------------------------------------
PROBLEM:
Ops team and onboarding practitioners need a focused administrative web console 
to inspect daily astronomical solar timings (Panchanga foundation) and browse, 
filter, and review verified astrologer profiles on both desktop and mobile 
screens without external backend dependencies, heavy component libraries, or 
alarmist copy.

TARGET USERS:
- Ritam Ops & Supply Team: Reviewing astrologer credentials and timings.
- Astrologers & Practitioners: Reviewing their published profile details on 
  mobile devices (down to 360px).

CORE FEATURES (SCOPE):
1. Solar Ephemeris Console (/):
   - Sunrise, sunset, day length, and solar noon calculations for 4 key Indian 
     observation nodes (Bengaluru, Kolkata, Delhi, Chennai).
   - Handles all 4 states: Idle/Loading, Success, Empty, Error (with retry).
2. Practitioner Directory (/practitioners):
   - Registry of verified practitioners.
   - Live filtering by language and specialism via derived state.
   - Result count ("Showing X of Y practitioners").
   - URL-synchronized sorting (?sort=experience-desc, name-asc).
   - Layout-holding 3-card skeleton loading state.
3. Practitioner Profile Detail (/practitioners/[id]):
   - Server Component view displaying pseudonym, price band, bio, languages, 
     and ethics covenant.
4. Local Mock API Handler (/api/practitioners):
   - GET: Query parameter filtering (?language=, ?specialism=).
   - POST: Validated practitioner registration endpoint.

STRICT NON-NEGOTIABLE CONSTRAINTS:
- Pure CSS with CSS custom properties (variables) defined at :root (FRE-109).
- Zero raw hex values in component stylesheets.
- No external UI component libraries (no Tailwind, Radix, shadcn, Chakra, MUI).
- No external state management (no Redux, Zustand).
- No external database or authentication layers.
- Filtering must be derived during render (never stored in useEffect).
- Responsive down to 360px without horizontal page scroll.
- Dark mode via prefers-color-scheme and :root[data-theme="dark"].
- 100% offline-passing test suite with 0 network calls.

--------------------------------------------------------------------------------
STEP 2: PRD -> TECH STACK
--------------------------------------------------------------------------------
- Framework: Next.js (App Router, JavaScript ESM)
- UI & Styling: Pure handwritten CSS with CSS Custom Properties (:root design tokens)
- State Management: React built-in useState + derived variables during render
- Data Layer: Local structured JSON (data/practitioners.json) + Route Handler
- External Integration: sunrise-sunset.org (lat, lng, date)
- Test Runner: Vitest (ESM, fast execution, parallel runner)
- Component Testing: React Testing Library + @testing-library/user-event + jest-dom
- Test Environment: jsdom (in-memory fake DOM)

--------------------------------------------------------------------------------
STEP 8: DEBUGGING GUIDE & SOLUTIONS
--------------------------------------------------------------------------------
1. Trap: API returns HTTP 200 with { status: "INVALID_REQUEST" }.
   Fix: Check json.status !== 'OK' after checking res.ok.
2. Trap: Out-of-order network responses when switching cities fast.
   Fix: Store AbortController in ref and call controller.abort() before each fetch.
3. Trap: Storing filtered list in useEffect causes double renders and stale data.
   Fix: Calculate const filtered = filterPractitioners(...) directly in render.
4. Trap: Flex items cause horizontal scroll at 360px.
   Fix: Set min-width: 0 on flex children and wrap wide tables in overflow-x: auto.
5. Trap: Dark mode toggle conflicts with OS theme.
   Fix: Support both @media (prefers-color-scheme: dark) and :root[data-theme] with 
   color-scheme CSS property.
